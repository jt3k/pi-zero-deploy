# Spec Delta

## Purpose

Определяет наблюдаемое поведение консольной команды `pizdeploy`: как она становится доступной в терминале пользователя, что выводит при успешном запуске и как ведёт себя при отсутствии необходимого рантайма.

## ADDED Requirements

### Requirement: Команда доступна в PATH

Система SHALL предоставлять исполняемую команду с именем `pizdeploy`, доступную в интерактивной оболочке пользователя (macOS, zsh или bash) после выполнения документированной установки из каталога проекта.

#### Scenario: Команда найдена после установки

- **WHEN** пользователь выполнил установку утилиты и в новой сессии терминала вводит `pizdeploy`
- **THEN** оболочка находит команду (выход `which pizdeploy` непустой) и запускает её без указания пути к проекту

#### Scenario: Установка без аргументов не требует прав root

- **WHEN** пользователь устанавливает команду из обычного пользовательского аккаунта macOS
- **THEN** установка завершается успешно без использования `sudo` и записи в системные каталоги

### Requirement: Успешный запуск выводит worked

Система SHALL при запуске команды `pizdeploy` вывести в stdout ровно строку `worked` с завершающим переводом строки, оставить stderr пустым и завершиться с кодом возврата 0.

#### Scenario: Обычный запуск

- **WHEN** пользователь выполняет `pizdeploy` в терминале
- **THEN** stdout содержит ровно `worked\n`
- **AND** код возврата равен 0
- **AND** stderr пуст

#### Scenario: Вывод пригоден для конвейера

- **WHEN** пользователь выполняет `pizdeploy | cat`
- **THEN** результатом конвейера является ровно одна строка `worked` без дополнительных служебных сообщений

### Requirement: Исполнение делегируется рантайму Bun

Система SHALL выполнять логику утилиты через рантайм Bun, запускаемый точкой входа команды, а не как самостоятельный скомпилированный бинарный файл.

#### Scenario: Bun отсутствует в PATH

- **WHEN** пользователь выполняет `pizdeploy`, а рантайм Bun не установлен или недоступен в PATH
- **THEN** утилита не выводит строку `worked`
- **AND** в stderr выводится сообщение, явно указывающее на отсутствие Bun и команду его установки
- **AND** код возврата равен 127

### Requirement: Поведение не зависит от текущего каталога

Система SHALL давать одинаковый результат запуска `pizdeploy` независимо от рабочего каталога и от того, запущена ли она внутри проекта.

#### Scenario: Запуск вне каталога проекта

- **WHEN** пользователь выполняет `pizdeploy` из произвольного каталога, например из домашней директории
- **THEN** в stdout появляется строка `worked` и код возврата равен 0

### Requirement: Аргументы командной строки вне объёма текущей версии

Система SHALL в текущей версии не разбирать аргументы командной строки: утилита остаётся заглушкой и обязана давать тот же результат, что и запуск без аргументов, при любом их наборе. Разбор субкоманд и флагов (`--help`, `--version`) будет введён отдельным изменением.

#### Scenario: Запуск с произвольными аргументами

- **WHEN** пользователь выполняет `pizdeploy --help` или `pizdeploy deploy prod`
- **THEN** stdout содержит ровно `worked\n`, stderr пуст, код возврата равен 0

#### Scenario: Аргументы не интерпретируются

- **WHEN** пользователь передаёт аргумент, который в будущем станет флагом
- **THEN** текущая версия не выдаёт по нему никакого сообщения и не меняет код возврата
