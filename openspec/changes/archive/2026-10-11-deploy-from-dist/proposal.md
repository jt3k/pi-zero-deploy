# Proposal

## Why

Утилита `pizdeploy` в текущем состоянии выполняет лишь демонстрационную команду `echo pwd` на удалённом хосте. Для решения реальной задачи деплоя проекта на Raspberry Pi требуется автоматизировать полный конвейер: локальную сборку, упаковку артефактов `dist`, вычисление детерминированного хэша релиза, надёжную доставку в каталог `incoming`, атомарное переключение симлинка `current`, перезапуск службы systemd и ротацию старых релизов без привлечения внешних тяжёлых библиотек (таких как `zx`).

## What Changes

- **Сборка и архивирование:**
  - Локальный запуск команды сборки `bun run build`.
  - Упаковка содержимого директории `dist` в компактный архив `dist.tar.gz` (`tar -czf ./dist.tar.gz -C ./dist .`).
  - Очистка временного архива `dist.tar.gz` в блоке гарантированной очистки (finally).
- **Детерминированное хэширование:**
  - Расчёт SHA-256 от полученного `dist.tar.gz` с использованием нативного криптографического API Bun (`new Bun.CryptoHasher("sha256")`).
  - Выделение первых 5 символов hex-хэша для формирования суффикса релиза: `<name>_<hash5>`.
  - Чтение имени проекта `<name>` из `package.json` (`pkg.name || "app"`).
- **Изолированная доставка и атомарное развёртывание:**
  - Создание изолированного каталога релиза `~/projects/<name>/incoming/<name>_<hash5>` на Raspberry Pi.
  - Копирование архива через `scp` в целевой каталог.
  - Распаковка архива на месте и удаление удалённого `dist.tar.gz`.
  - Атомарное переключение симлинка `current` (`ln -sfn ... current_tmp && mv -fT current_tmp current`).
  - Перезапуск службы systemd (`sudo systemctl restart <service>`, по умолчанию `app.service`).
  - Ротация релизов в `incoming/` с сохранением последних 3 версий.
- **Поддержка Dry-Run и расширение CLI:**
  - Добавление флага `--dry-run` в разбор аргументов (`parseArgs`).
  - В режиме `--dry-run` вывод плана действий и пути назначения без выполнения сборки и сетевых мутаций.
  - Сохранение гибкого разрешения адреса подключения (`--ssh`, `package.json.pizdeploy.ssh`, `pi@zero.local`).
- **BREAKING Замена демонстрационной команды:**
  - Замена выполнения тестовой команды `echo 'pwd: ...'` на полноценный сценарий деплоя.

## Capabilities

### New Capabilities

- `dist-deploy`: Сборка проекта (`bun run build`), архивирование директории `dist`, вычисление детерминированного 5-символьного SHA-256 хэша релиза, изолированная доставка архива в `incoming/`, атомарное переключение симлинка `current`, перезапуск службы systemd, ротация старых релизов и режим `--dry-run`.

### Modified Capabilities

- `cli-command`: Добавление флага `--dry-run` в допустимые опции CLI; запуск в режиме предварительного просмотра.
- `remote-exec`: Удаление требования выполнения тестовой заглушки `echo pwd: <cwd>` в пользу команд деплоя, распаковки и управления сервисом.

## Impact

- **Кодовая база:** адаптация `src/index.ts` с переходом на нативные возможности Bun 1.4 (без сторонней зависимости `zx`).
- **CLI опции:** флаги `--ssh <host>` и `--dry-run`.
- **Интеграционные тесты:** обновление `test/cli.test.ts` для проверки этапов сборки, хэширования, формирования путей, dry-run и вызовов SSH/SCP.
- **Документация:** актуализация `README.md` с описанием нового пайплайна развёртывания.
