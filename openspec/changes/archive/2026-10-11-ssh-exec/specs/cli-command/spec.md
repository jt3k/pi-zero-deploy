# Spec Delta

## ADDED Requirements

### Requirement: Флаг --ssh задаёт адрес подключения

Система SHALL принимать флаг `--ssh <user@host>` в любом месте аргументов командной строки, в том числе в форме `--ssh=<user@host>`, и передавать его значение как адрес подключения.

#### Scenario: Флаг со значением через пробел

- **WHEN** пользователь выполняет `pizdeploy --ssh pi@other.local`
- **THEN** адресом подключения становится `pi@other.local`

#### Scenario: Флаг со значением через знак равенства

- **WHEN** пользователь выполняет `pizdeploy --ssh=pi@other.local`
- **THEN** адресом подключения становится `pi@other.local`

### Requirement: Ошибки использования завершаются кодом 2

Система SHALL завершаться с кодом возврата 2 и сообщением в stderr при неизвестном аргументе, отсутствующем значении `--ssh`, пустом адресе подключения или адресе, который после удаления обрамляющих пробелов начинается с `-`.

#### Scenario: Неизвестный аргумент

- **WHEN** пользователь выполняет `pizdeploy --help` или `pizdeploy deploy prod`
- **THEN** в stderr появляется сообщение, содержащее `usage`
- **AND** stdout пуст
- **AND** код возврата равен 2

#### Scenario: --ssh без значения

- **WHEN** пользователь выполняет `pizdeploy --ssh`
- **THEN** в stderr появляется сообщение, содержащее `usage`
- **AND** stdout пуст
- **AND** код возврата равен 2

#### Scenario: Пустой адрес

- **WHEN** значение `--ssh` пусто или состоит только из пробелов
- **THEN** в stderr появляется сообщение, содержащее `usage`
- **AND** код возврата равен 2
- **AND** подключение не выполняется

#### Scenario: Адрес начинается с дефиса

- **WHEN** значение `--ssh` после удаления обрамляющих пробелов начинается с `-`
- **THEN** в stderr появляется сообщение, содержащее `usage`
- **AND** код возврата равен 2
- **AND** подключение не выполняется

## MODIFIED Requirements

### Requirement: Исполнение делегируется рантайму Bun

Система SHALL выполнять логику утилиты через рантайм Bun, запускаемый точкой входа команды, а не как самостоятельный скомпилированный бинарный файл.

#### Scenario: Bun отсутствует в PATH

- **WHEN** пользователь выполняет `pizdeploy`, а рантайм Bun не установлен или недоступен в PATH
- **THEN** утилита не выполняет подключение и не выводит результат удалённой команды
- **AND** в stderr выводится сообщение, явно указывающее на отсутствие Bun и команду его установки
- **AND** код возврата равен 127

### Requirement: Поведение не зависит от текущего каталога

Система SHALL запускаться одинаково независимо от того, запущена ли она внутри каталога проекта: точка входа находит исполняемый код по своему реальному пути, а не по каталогу вызова.

#### Scenario: Запуск вне каталога проекта

- **WHEN** пользователь выполняет `pizdeploy` из произвольного каталога, например из домашней директории
- **THEN** утилита запускается и доходит до выполнения удалённой команды
- **AND** код возврата определяется результатом этой команды, а не каталогом вызова

## REMOVED Requirements

### Requirement: Успешный запуск выводит worked

**Reason**: Заглушка `worked` не выполняет полезного действия. Её место заняло подключение к целевому хосту и вывод результата удалённой команды (способность `remote-exec`).

**Migration**: Ожидаемый вывод `pizdeploy` — `pwd: <текущий рабочий каталог>` вместо `worked`. Конвейеры и скрипты, сверявшие строку `worked`, нужно поправить.

### Requirement: Аргументы командной строки вне объёма текущей версии

**Reason**: Появляется разбор флага `--ssh`; аргументы больше не игнорируются.

**Migration**: Использовать требования «Флаг --ssh задаёт адрес подключения» и «Ошибки использования завершаются кодом 2». Неизвестные аргументы (`--help`, `deploy prod`) теперь дают ошибку использования и код 2 вместо вывода `worked`.
