# Design

## Context

Мотивация и цели изменений приведены в `proposal.md`.
В проекте удалена лишняя промежуточная оболочка `bin/pizdeploy`: исполняемый файл `src/index.ts` снабжён шебангом `#!/usr/bin/env bun` и напрямую зарегистрирован в поле `bin.pizdeploy` файла `package.json`.
Подготовлен и поддерживается исчерпывающий набор интеграционных тестов в `test/cli.test.ts`.

## Goals / Non-Goals

**Goals:**
- Удаление всего отладочного мусора из корня репозитория и добавление `.gitignore`.
- Минималистичная, надежная и ультракомпактная реализация `src/index.ts` (< 35 строк) без внешних зависимостей.
- Прямой запуск через шебанг `#!/usr/bin/env bun` без лишних обёрток.
- Корректная обработка аргументов командной строки (`--ssh <value>`, `--ssh=<value>`, дублирование флагов, невалидные аргументы → код 2 и usage в stderr) через встроенный `parseArgs` из `"util"`.
- Чтение `package.json` исключительно в текущем рабочем каталоге `process.cwd()` без обхода дерева папок.
- Разрешение хоста через лаконичную цепочку `flagSsh || pkg?.pizdeploy?.ssh || DEFAULT_HOST`.
- Безопасное формирование удалённой команды `echo 'pwd: <cwd>'` с экранированием одинарных кавычек.
- Запуск системного `ssh` через Bun Shell `$` с флагами `-o BatchMode=yes -o ConnectTimeout=3`, проброс вывода и кода возврата, корректная обработка отсутствия `ssh` через `Bun.which` (код 127).
- Прохождение 100% тестов `bun test`.

**Non-Goals:**
- Введение сторонних npm-пакетов или утилит парсинга аргументов.
- Любая избыточная валидация адреса (проверки на дефис, формат, сетевую доступность до вызова ssh).
- Поддержка субкоманд, флагов `--help`/`--version` (вне скоупа текущей версии).
- Оболочка-обёртка для проверки наличия Bun.

## Decisions

### D1. Наведение порядка в файловой структуре
- Удаление временных файлов `.probe.ts` и директории `.probe/`.
- Удаление промежуточной обёртки `bin/pizdeploy`; входная точка — напрямую `src/index.ts`.
- Добавление стандартного `.gitignore` для Node/Bun проектов (`node_modules/`, `.DS_Store`, временные файлы отладки).

### D2. Встроенный `parseArgs` из `util` вместо самописных парсеров
Используется стандартный встроенный парсер `parseArgs` из `"util"`, полностью поддерживаемый Bun 1.4:
```ts
const { values } = parseArgs({
  args: argv,
  options: { ssh: { type: "string" } },
  strict: true,
});
```
- Из коробки поддерживает `--ssh <val>`, `--ssh=<val>` и перезапись при повторном флаге.
- При неизвестных флагах, позиционных аргументах или `--ssh` без значения выбрасывает стандартные ошибки `ERR_PARSE_ARGS_*`.
- Ошибки перехватываются в блоке `catch`, выводят `usage: pizdeploy [--ssh <user@host>]` в stderr и возвращают код 2.

### D3. Чтение конфигурации и лаконичная цепочка разрешения хоста
Чтение `package.json` выполняется только в текущем рабочем каталоге `process.cwd()` через быстрый нативный API `Bun.file("package.json").json()`:
```ts
const pkg = await Bun.file("package.json").json().catch(() => ({}));
const host = flagSsh || pkg?.pizdeploy?.ssh || DEFAULT_HOST;
```
Если файл отсутствует в текущей директории или содержит некорректный JSON, ошибка безопасно поглощается `catch(() => ({}))`, и адрес разрешается в дефолтный `DEFAULT_HOST = "pi@zero.local"`. Поиск вверх по дереву не выполняется. Лишний `.trim()` не навязывается.

### D4. Безопасное формирование удалённой команды
Строка формируется в одинарных кавычках POSIX с нативным `.replaceAll("'", "'\\''")`:
```ts
const remoteCmd = `echo 'pwd: ${process.cwd().replaceAll("'", "'\\''")}'`;
```
Это предотвращает выполнение кода на сервере при наличии спецсимволов в имени каталога.

### D5. Выполнение SSH через Bun Shell и проверка через `Bun.which`
Выполнение удалённой команды через Bun Shell (`import { $ } from "bun"`):
```ts
if (!Bun.which("ssh")) {
  console.error("pizdeploy: ssh не найден в PATH. Установите OpenSSH.");
  return 127;
}

return (await $`ssh -o BatchMode=yes -o ConnectTimeout=3 ${host} ${remoteCmd}`.nothrow()).exitCode;
```
- Доступность клиента `ssh` в `PATH` проверяется встроенной функцией `Bun.which("ssh")`. Если бинарник не найден — выводится сообщение в stderr и возвращается код 127.
- Запуск команды осуществляется через шаблонную строку Bun Shell `$`. Метод `.nothrow()` обеспечивает возврат объекта с `exitCode` без выбрасывания исключения на ненулевых кодах завершения SSH.

## Risks / Trade-offs

- [Риск: Bun Shell по умолчанию выбрасывает ShellError на ненулевых кодах] → Использование `.nothrow()` гарантирует прозрачный проброс `exitCode`.
- [Риск: экранирование путей с нестандартными символами] → Покрыто тестами в `test/cli.test.ts` (пути с пробелами, кавычками, спецсимволами).
