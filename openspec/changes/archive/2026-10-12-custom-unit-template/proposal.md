# Proposal

## Why

Сейчас unit-файл systemd жестко генерируется в коде функции `renderUnit()`. Разработчик не может передать кастомные переменные окружения (например, токены ботов, флаги конфигурации) или политики процесса через файл шаблона в проекте. При этом вписывать в шаблон параметры запуска (`WorkingDirectory`, `ExecStart`) вручную нежелательно — это приводит к дублированию и рассинхронизации при изменении скрипта `package.json:scripts.start`.

Необходимо ввести поддержку файла `systemd-unit.service` в корне деплоящего проекта (а при его отсутствии — дефолтного эталона из `pizdeploy`). В шаблоне проекта указываются только специфичные настройки (описание, переменные окружения, политики рестарта), а динамические параметры выполнения (`WorkingDirectory` и `ExecStart`) автоматически внедряются утилитой из контекста релиза.

## What Changes

1. **Эталонный шаблон `systemd-unit.service` в корне `pizdeploy`**:
   - Служит базовым шаблоном по умолчанию с `Environment="NODE_MODULES=production"`, `Restart=always`, `RestartSec=2`.

2. **Приоритет выбора шаблона**:
   - Если в корне деплоящего проекта есть `systemd-unit.service` (как, например, в Telegram-ботах с собственным набором `Environment=`), утилита использует его.
   - Если файл в проекте отсутствует, используется дефолтный `systemd-unit.service` из `pizdeploy`.

3. **Автоматическая инжекция рабочих путей и команды старта**:
   - Утилита гарантирует, что в секцию `[Service]` подставляются:
     - `WorkingDirectory=/home/pi/projects/<name>/current`
     - `ExecStart=<resolved-node-exec>` (на основе обязательного `package.json:scripts.start`).
   - Если эти поля отсутствовали в пользовательском шаблоне, они добавляются; если присутствовали — приводятся к актуальным значениям релиза.
   - Если `Description=` не задан, подставляется имя пакета `name`.

4. **Установка на целевом хосте**:
   - Итоговый юнит сохраняется на целевой хост в `~/.config/systemd/user/<service-name>.service` строго под каноничным именем службы.

## Capabilities

### Modified Capabilities

- `user-unit-runtime`: формирование unit-файла на основе шаблона `systemd-unit.service` (из проекта или встроенного), автоматическое внедрение `WorkingDirectory` и `ExecStart` из `scripts.start`, сохранение кастомных переменных окружения проекта и установка под именем `<service>.service`.

## Impact

- Добавляется файл `systemd-unit.service` в корень репозитория `pizdeploy`.
- В `src/index.ts` обновляется функция формирования юнита `renderUnit`.
- Обновляются тесты в `test/deploy.test.ts`.
- Обновляется документация в `README.md`.
