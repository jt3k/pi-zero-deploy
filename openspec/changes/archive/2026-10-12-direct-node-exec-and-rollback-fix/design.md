# Design

## Context

Замеры на целевом хосте (`pi@zero.local`, Raspberry Pi Zero, 1-ядерный ARMv6):
- Прямой запуск `node -e "..."` занимает **~5.0 с** (CPU: 4.7 с).
- Запуск через `npm start` занимает **~26.3 с** (CPU: 25.1 с) из-за накладных расходов на чтение и парсинг инфраструктуры npm CLI на слабом одноядерном процессоре.
- В собранном архиве деплоя содержится только каталог `./dist/`, файл `package.json` в распакованный релиз не попадает.
- При первом деплое `readlink -f <project>/current` возвращает строку пути, так как симлинк ещё не существует. При отказе верификации попытка создать симлинк на этот результат создавала циклическую ссылку `current -> current`.

## Goals / Non-Goals

**Goals:**

- Обязательная валидация команды старта: проект обязан иметь непустой `package.json:scripts.start`.
- Формирование `ExecStart` в user-юните напрямую из `scripts.start`, исключая зависимость от `npm` и `package.json` в релизе.
- Корректный откат: если предыдущего релиза не было, при отказе верификации удалять симлинк `current`, а не циклически ссылать его на себя.
- Снижение таймаутов верификации со 180 с до 60 с благодаря быстрому старту процесса.

**Non-Goals:**

- Поддержка проектов без `package.json` или без `scripts.start` (любая эвристика по поиску входного файла исключена).
- Копирование `package.json` в релиз (релиз остается чистым каталогом `dist`).

## Decisions

### 1. Строгая валидация scripts.start в CLI

Перед сборкой и сетевыми вызовами CLI проверяет:
```ts
const startScript = pkg?.scripts?.start;
if (!startScript || typeof startScript !== "string" || !startScript.trim()) {
  console.error("pizdeploy: в package.json отсутствует обязательный скрипт 'scripts.start'");
  return 1;
}
```
*Альтернатива:* использовать эвристику `node index.js`. Отклонено: проект может требовать специальные флаги, транспайлеры или другое имя файла; неявные дефолты приводят к трудноуловимым ошибкам на проде.

### 2. Формирование ExecStart

Команда нормализуется для systemd:
- Если команда начинается с `node `, путь к бинарнику дополняется до абсолютного `/usr/bin/node` (или берется текущий путь node на хосте).
- Если в команде указан путь относительно корня репозитория (например, `dist/index.js`), а `WorkingDirectory` указывает на `current` (куда распаковано содержимое `dist`), путь адаптируется к каталогу запуска.
- Для сложных команд (с переменными, пайпами) используется обёртка `/bin/sh -c "<command>"`.

### 3. Исправление логики отката симлинка current

Откат должен проверять, что `prevTarget` реально существовал как директория:
```bash
if [ -d "${prevTarget}" ] && [ "${prevTarget}" != "${currentLink}" ]; then
  ln -sfn "${prevTarget}" ... && mv ...
else
  rm -f "${currentLink}" "${projectDir}/current_tmp"
fi
```
Это полностью предотвращает появление циклических ссылок `current -> current`.

### 4. Оптимизация таймаутов

- `VERIFY_TIMEOUT_MS`: уменьшается со 180 000 мс до 60 000 мс (запас в 12x от реальных 5 секунд старта node на Pi Zero).

## Risks / Trade-offs

- [В `scripts.start` используются пути с префиксом `dist/`] → Команда парсится с учетом того, что артефакты из `dist/` распакованы прямо в корень релиза; если указан `dist/index.js`, утилита проверяет наличие файла в распакованном каталоге и запускает `node index.js`.
- [В `scripts.start` передаются локальные dev-инструменты (`ts-node`, `nodemon`)] → Такие инструменты упадут на проде. Митигация: валидное сообщение об ошибке верификации службы с быстрым откатом.
