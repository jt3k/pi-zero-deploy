# Proposal

## Why

Реальная проверка деплоя на хосте `pi@zero.local` выявила два дефекта:
1. Юнит-файл жестко выполняет `ExecStart=/usr/bin/npm start`, в то время как архив релиза содержит только скомпилированный `dist/` без `package.json`. В результате `npm start` завершается с кодом ошибки (`status=200/CHDIR` или отсутствие скрипта), а запуск через `npm` на 1-ядерном ARMv6 занимает ~26 секунд вместо ~5 секунд прямого запуска Node.
2. При первом деплое проекта, когда симлинк `current` ещё не создан, попытка отката при неудачной верификации создаёт циклический симлинк `current -> current`, ломая последующие запуски.

## What Changes

- **Валидация команды запуска проекта (BREAKING):** Проект обязан явно определять команду запуска в `package.json:scripts.start`. Если скрипт отсутствует или пуст, `pizdeploy` прерывает работу с ошибкой до передачи файлов на хост. Никаких эвристик и неявных дефолтов не применяется.
- **Прямой запуск команды в unit-файле (BREAKING):** Вместо вызова `npm start` утилита формирует `ExecStart` в сгенерированном user-юните на основе команды из `scripts.start`, адаптируя путь запуска к рабочему каталогу релиза.
- **Корректный откат симлинка при первом деплое:** Откат `current` выполняется только если целевой релиз реально существовал до начала развёртывания. Если `current` отсутствовал, при сбое верификации симлинк просто удаляется, исключая зацикливание на самого себя.
- **Оптимизация таймаутов верификации:** Поскольку прямой запуск процесса на Pi Zero выполняется за секунды (вместо ~26 с через npm), таймаут ожидания перехода в `active` снижается со 180 с до 60 с.

## Capabilities

### Modified Capabilities

- `user-unit-runtime`: Изменяется каноничный способ запуска в юните — переход от вызова `npm start` к прямому исполнению команды из `scripts.start`, а также требование обязательного наличия валидного `scripts.start` в деплоящем проекте.
- `deploy-pipeline`: Уточняется контракт отката симлинка `current` при сбое верификации для случая первого развёртывания проекта.

## Impact

- **Код:** `src/index.ts` — парсинг `pkg.scripts.start`, функция `renderUnit`, шаг отката при сбое верификации, константы таймаутов.
- **Спецификации:** `openspec/specs/user-unit-runtime/spec.md`, `openspec/specs/deploy-pipeline/spec.md`.
- **Тесты:** `test/deploy.test.ts`, `test/cli.test.ts` — тесты на валидацию `scripts.start`, шаблон `ExecStart`, безопасный откат при первом деплое.
- **Документация:** `README.md` — актуализация требований к `package.json` и описания сгенерированного юнита.
