# Design

## Context

В проектах, требующих секретных переменных окружения (например, токены ботов, API ключи), пользователю необходимо иметь локальный шаблон `systemd-unit.service` в корне проекта.
Команда `pizdeploy init` предоставляет простой способ инициализировать такой шаблон.

## Goals / Non-Goals

**Goals:**
- Реализовать подкоманду `init` в CLI без обращения к сети и без вызова компиляции/деплоя.
- Проверять наличие `package.json` в текущей рабочей директории и выводить предупреждение при его отсутствии.
- Читать `name` из `package.json` и предзаполнять `Description=<name>`.
- Предотвращать случайную перезапись уже существующего `systemd-unit.service`.
- Исправить опечатку `NODE_MODULES=production` на стандартное `NODE_ENV=production` во всех шаблонах и тестах.

**Non-Goals:**
- Интерактивный опрос параметров через консоль (prompt/inquirer) — файл создается сразу с чистыми настройками и комментариями, что быстрее и проще для пользователя.
- Автоматическая остановка первого деплоя (поведение Варианта Г: при деплое без файла используется эталонный fallback, создание файла происходит только по явной команде `init`).

## Decisions

### 1. Сигнатура и обработка `init` в CLI
`init` добавляется как позиционная подкоманда наравне с `ps`, `start`, `stop`, `restart`, `status`, `logs`, `disable`, `remove`, `rm`:
```ts
if (command === "init") {
  return await handleInit();
}
```

### 2. Шаблон, генерируемый командой `init`
```ini
[Unit]
Description=<name>
After=default.target

[Service]
Type=simple
Restart=always
RestartSec=2
Environment="NODE_ENV=production"
# Добавьте переменные окружения и секреты:
# Environment="BOT_TOKEN=..."

[Install]
WantedBy=default.target
```
В файле намеренно отсутствуют `WorkingDirectory` и `ExecStart`, так как они подставляются утилитой при деплое автоматически.

### 3. Исправление `NODE_MODULES=production` на `NODE_ENV=production`
- Заменяем в эталонном файле `systemd-unit.service` в корне репозитория.
- Заменяем в дефолтной строке в `renderUnit` в `src/index.ts`.
- Обновляем соответствующие проверки в `test/deploy.test.ts`.

## Risks / Trade-offs

- **[Риск]** Пользователь вызвал `init` в пустой папке без `package.json`.
  → *Митигация:* Проверяем `existsSync(resolve(process.cwd(), "package.json"))`. Если нет — выводим сообщение с предупреждением и выходим с кодом 1, не создавая пустых полузаполненных файлов.
- **[Риск]** Пользователь случайно вызвал `init` в проекте, где уже настроен сложный unit-файл.
  → *Митигация:* Проверяем `existsSync(resolve(process.cwd(), "systemd-unit.service"))`. Если файл есть — ничего не перезаписываем, выводим информирующее сообщение и выходим с кодом 0.
