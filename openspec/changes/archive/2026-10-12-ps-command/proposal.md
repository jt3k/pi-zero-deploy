# Proposal

## Why

При разработке и деплое нескольких сервисов на одной микро-ноде (Raspberry Pi) разработчику сложно контролировать, какие именно приложения задеплоены, какие из них реально запущены, какие системные службы к ним привязаны и какие сетевые порты заняты. В настоящий момент `pizdeploy` выполняет только операцию деплоя текущего проекта вслепую, что приводит к коллизиям портов, рассинхрону имён служб и непониманию, работает ли приложение на целевом хосте. Требуется легковесная команда инспекции состояния без развёртывания тяжёлых систем мониторинга.

## What Changes

- **Подкоманда `pizdeploy ps`:**
  - Расширение интерфейса командной строки поддержкой подкоманды `ps` (`pizdeploy ps [--ssh <user@host>]`).
  - При запуске `pizdeploy ps` сборка проекта (`bun run build`), локальная упаковка и деплой не выполняются.
  - Поддержка единых правил разрешения адреса хоста (флаг `--ssh`, поле `pizdeploy.ssh` в `package.json`, либо дефолтный `pi@zero.local`).
- **Сбор статуса сервисов на удалённом хосте:**
  - Быстрый сбор активных слушающих сокетов и PID через сетевой стек ОС (`ss -tlpn`) без необходимости прав `sudo`.
  - Определение привязки процесса к проекту через чтение текущей директории ядра (`/proc/<pid>/cwd`).
  - Определение ассоциированной службы systemd через чтение контрольной группы ядра (`/proc/<pid>/cgroup`).
  - Инспекция задеплоенных проектов в `/home/pi/projects/*` и активных версий по симлинку `current`.
- **Наглядное отображение таблицы статусов:**
  - Использование встроенного API Bun `console.table()` для отображения выровненной таблицы без внешних зависимостей.
  - Автоматическое формирование кликабельных ссылок вида `http://<host>:<port>` для сервисов, слушающих сетевые порты.

## Capabilities

### New Capabilities
- `service-discovery`: Инспекция состояния удалённого сервера: обнаружение задеплоенных проектов в `~/projects/`, определение активных релизов, сбор слушающих портов и ассоциированных служб systemd через `/proc` и `ss`, а также отображение форматированной таблицы с кликабельными URL.

### Modified Capabilities
- `cli-command`: Поддержка подкоманды `ps` в разборе аргументов CLI; актуализация usage строки (`pizdeploy [ps] [--ssh <user@host>] [--dry-run]`).

## Impact

- **CLI и точка входа:** обновление парсера аргументов в `src/index.ts` для ветвления логики при передаче команды `ps`.
- **Зависимости:** нулевое влияние (используются исключительно нативные возможности Bun и стандартные утилиты Linux `/proc` и `ss`).
- **Тестирование:** добавление тестов на разбор подкоманды `ps`, передачу аргументов в SSH и форматирование вывода в `test/cli.test.ts`.
