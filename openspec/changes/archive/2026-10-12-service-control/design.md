# Design

## Context

После развёртывания проектов и проверки состояния через `pizdeploy ps` возникает необходимость оперативно управлять службами: останавливать работающие процессы для высвобождения ресурсов или отключать автозапуск неиспользуемых сервисов. См. `proposal.md` - Why.
Все команды выполняются через мультиплексированное SSH-соединение на целевом устройстве Raspberry Pi.

## Goals / Non-Goals

**Goals:**
- Реализовать две независимые подкоманды:
  - `pizdeploy stop [name]` — немедленная остановка процесса службы (`systemctl stop`).
  - `pizdeploy disable [name]` — отключение автозапуска службы в systemd (`systemctl disable`).
- Поддержать два сценария передачи имени:
  1. Без аргумента `[name]` — имя службы извлекается из текущего `package.json` (`pizdeploy.service` или `${name}.service`, по умолчанию `app.service`).
  2. С аргументом `[name]` — прямое управление указанной службой (например, `pizdeploy stop my-app` или `pizdeploy stop pi-zero-deploy-lite.service`).
- Автоматически нормализовать имя: если передан аргумент без суффикса `.service`, дописывать его (`my-app` -> `my-app.service`).
- Выводить наглядные эмодзи-сообщения о результате выполнения.

**Non-Goals:**
- Удаление каталогов проекта с файловой системы хоста (undeploy/purge) — команды затрагивают только состояние systemd.
- Перезапуск службы (`restart`) — это действие уже является частью стандартного конвейера деплоя.

## Decisions

### 1. Диспетчеризация команд и нормализация аргументов

- **Выбор:** Парсить позиционные аргументы: первый аргумент — команда (`ps`, `stop`, `disable`), второй (опциональный) — имя службы/проекта.
- **Обоснование:** Сохраняет совместимость с существующим `parseArgs({ allowPositionals: true })` и исключает двусмысленность.
- **Правило нормализации имени:**
  ```ts
  function normalizeService(name: string): string {
    return name.endsWith(".service") ? name : `${name}.service`;
  }
  ```

### 2. Безопасное выполнение на удалённом хосте

- **Выбор:** Перед вызовом `sudo systemctl stop/disable` удалённый скрипт проверяет наличие службы через `systemctl cat <service> >/dev/null 2>&1`.
- **Обоснование:** Если служба отсутствует в системе, утилита сразу сообщает об ошибке с точным именем юнита и возвращает код 1, не засоряя консоль системным stacktrace.

### 3. Единые правила подключения SSH

- **Выбор:** Команды `stop` и `disable` используют те же опции подключения и переиспользуют `ControlMaster` сокет, что и основной деплой и команда `ps`.

## Risks / Trade-offs

- **[Права sudo для systemctl]** → Команды `systemctl stop` и `systemctl disable` требуют прав суперпользователя. *Митигация:* На Raspberry Pi утилита опирается на стандартную настройку `sudoers` без пароля для `systemctl`. При ошибке прав stderr команды выводится пользователю.
