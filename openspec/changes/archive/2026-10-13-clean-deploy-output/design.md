# Design

## Context

В текущей реализации `src/index.ts` после успешной активации юнита и проверки доступности порта выполняется блок вывода:
```typescript
const hostname = host.replace(/^.*@/, "");
console.log(`🎉 Успешно развернут релиз: ${relId}`);
console.log(`   Служба: ${service} (systemctl --user, ${hostname})`);
console.log(port ? `   URL: http://${hostname}:${port}` : "   порт не задан (pizdeploy.port) — проверка прослушивания пропущена");
```
Это приводит к избыточным строкам в терминале.

## Goals / Non-Goals

**Goals:**
- Очистить консольный вывод успешного деплоя от шума: убрать имя службы и сообщение об отсутствии порта.
- Если `port` задан, выводить только строку с URL: `   URL: http://${hostname}:${port}`.
- Если `port` отсутствует, выводить только заголовок с релизом `🎉 Успешно развернут релиз: ${relId}`.
- Обновить unit/интеграционные тесты `test/deploy.test.ts`.

**Non-Goals:**
- Менять поведение валидации, тайминги ожидания запуска или проверку порта.
- Менять форматирование других команд (`pizdeploy ps`, `pizdeploy restart` и т.д.).

## Decisions

### 1. Формирование финального вывода в `src/index.ts`
Вместо безусловного вывода строки службы и тернарного оператора с сообщением о пропуске проверки:
- Удалить `console.log(\`   Служба: ${service} (systemctl --user, ${hostname})\`);`.
- Заменить вывод строки порта на условие:
  ```typescript
  if (port) {
    console.log(`   URL: http://${hostname}:${port}`);
  }
  ```
*Альтернатива*: Оставить пустую строку или тире при отсутствии порта. Отклонено: для ботов и фоновых сервисов порт не нужен вовсе, поэтому лишние строки только загромождают вывод.

### 2. Синхронизация тестов в `test/deploy.test.ts`
В `test/deploy.test.ts`:
- Заменить проверки, где ожидались `"Служба: ..."` и `"порт не задан ..."`, на проверку наличия только `"🎉 Успешно развернут релиз:"` и, при наличии порта, `"URL: http://..."`.
- Добавить негативную проверку: `expect(result.stdout).not.toContain("Служба:")` и `expect(result.stdout).not.toContain("порт не задан")`.

## Risks / Trade-offs

- [Risk] Сторонние скрипты могут парсить stdout деплоя в поисках строки `Служба:`.
  → Митигация: `pizdeploy` ориентирован на интерактивный CLI-опыт разработчика; для статусов и информации о службах каноничной является команда `pizdeploy ps`.
