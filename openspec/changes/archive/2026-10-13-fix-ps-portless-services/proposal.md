# Proposal

## Why

Команда `pizdeploy ps` обнаруживает запущенные процессы только через `ss -tlpn` — утилиту, которая показывает процессы, слушающие TCP-порты. Сервисы без прослушивающего порта (telegram-боты, воркеры, крон-задачи) никогда не попадают в массив `ports`, и их статус навсегда остаётся `inactive` с прочерками вместо PID. Проблема уже наблюдается у реальных проектов `kms` и `noproud`.

Одновременно столбец `Service` (имя systemd-юнита, например `my-app.service`) дублирует информацию из `Project` и `Release`, добавляя к имени проекта лишь суффикс `.service` — польза минимальна, а место в таблице занимает.

## What Changes

- Скрипт обнаружения процессов (`buildPsScript`) SHALL дополнительно искать запущенные процессы через `systemctl --user` для каждого проекта, у которого не найден слушающий порт. Это позволит корректно определять статус, PID и имя сервиса для процессов без открытых портов.
- Столбец `Service` SHALL быть удалён из таблицы `pizdeploy ps`: он дублирует уже присутствующую информацию. Поле `service` из JSON-ответа удалённого скрипта также удаляется.
- Тесты SHALL быть обновлены для покрытия нового поведения и удалённого столбца.

## Capabilities

### New Capabilities

_Нет новых capability — изменение расширяет существующее поведение._

### Modified Capabilities

- `service-discovery`: Требование «Сбор активных слушающих процессов и служб systemd» расширяется для обнаружения процессов без открытых TCP-портов. Требование «Форматирование таблицы статусов» изменяется: убирается столбец `Service`.

- **Обратная совместимость**: убирается столбец `Service` из CLI-вывода. Это не является API — это человекочитаемый терминальный вывод, не предназначенный для машинного парсинга. **BREAKING** для скриптов, парсящих `pizdeploy ps` (маловероятно).
