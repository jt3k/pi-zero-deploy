# Design

## Context

В текущей версии `pizdeploy`:
- В шаге 1 конвейера всегда безусловно вызывается `bun run build`.
- Если у пользователя проект без бандлера (простой `app.js` или микросервис), деплой завершается ошибкой `Script not found "build"`.
- При этом копирование целой папки `node_modules` на Raspberry Pi Zero по сети крайне неэффективно, а запуск `npm install` на слабом процессоре ARMv6 может подвесить систему или вызвать Out-Of-Memory.
- `bun build` является сверхбыстрым встроенным бандлером, который может автономно упаковать входной файл и все его внешние зависимости в компактный одиночный `.mjs` с tree-shaking и минификацией.

## Goals / Non-Goals

**Goals:**
- Полностью сохранить существующее поведение для проектов, у которых задан скрипт `scripts.build`.
- Для проектов без `scripts.build` реализовать надёжное эвристическое извлечение входного файла из `scripts.start`.
- Автоматически собирать оптимизированный ESM-бандл через `bun build '<entry>' --target=node --outfile=./dist/<name>.mjs --minify`.
- Настроить `ExecStart` в создаваемом systemd-юните так, чтобы он запускал сгенерированный `<name>.mjs`, сохраняя переданные аргументы и флаги Node.js.
- При невозможности распознать команду в `scripts.start` выводить дружелюбное сообщение с объяснением и рекомендацией.

**Non-Goals:**
- Парсинг и поддержка произвольных сторонних рантаймов (python, go, кастомные бинарники) в этой итерации.
- Изменение соглашений о каталоге релизов и структуре папок на сервере (`releases/`, `current`).

## Decisions

### Решение 1: Эвристический парсер `scripts.start`
- **Алгоритм**:
  1. Разбиваем строку `scripts.start` на токены.
  2. Проверяем, что запуск происходит через `node` (например, `node`, `/usr/bin/node`, `bun`):
     - Если команда не начинается с известного рантайма или в ней нет явного файла, парсер пытается найти токен с расширением `.js`, `.mjs`, `.cjs`, `.ts`.
  3. Извлекаем:
     - Опции рантайма (все токены до файла, начинающиеся с `-` или `--`).
     - Путь к файлу-точке входа (например, `./src/app.js`, `app.js`).
     - Аргументы приложения (все токены после файла, если есть).
  4. Если входной файл найден на диске:
     - Вычисляем базовое имя: `const base = path.basename(entryFile, path.extname(entryFile))`.
     - Назначаем выходной файл: `./dist/${base}.mjs`.
     - Команда для `ExecStart`: `/usr/bin/node ${nodeFlags} ${base}.mjs ${appArgs}`.
  5. Если входной файл не найден на диске или не распознан:
     - Завершаем деплой с кодом ошибки и выводом:
       ```
       pizdeploy: не удалось определить входной файл для автоматической сборки из scripts.start: "..."
       💡 Добавьте скрипт "build" в package.json (например: "build": "bun build ./app.js --target=node --outfile=./dist/app.mjs")
          или укажите прямой путь к запускаемому JS/TS файлу в scripts.start: "node ./app.js".
       ```

### Решение 2: Формат выходного бандла `.mjs`
- **Обоснование**:
  - `bun build` компилирует в современный ESM.
  - Расширение `.mjs` гарантирует, что Node.js 20 на Raspberry Pi выполнит файл как ES-модуль, даже если в `package.json` проекта отсутствует `"type": "module"`.
  - Флаг `--minify` обеспечивает минимальный размер передаваемого по Wi-Fi архива и быстрый парсинг V8 на Pi Zero.

## Risks / Trade-offs

- **[Риск]** Пользовательский код использует динамический `require(переменная)` или нативные аддоны (`.node`), которые бандлер не может статически включить.
  → **Митигация**: `bun build` при невозможности включить модуль оставляет его внешним либо выводит понятный build error. В таком случае пользователь всегда может объявить свой явный `scripts.build` с нужными флагами.
- **[Риск]** `scripts.start` содержит запуск через `npm run ...` или цепочку шелл-команд (`export FOO=1 && node app.js`).
  → **Митигация**: Эвристический парсер проверяет команду; если она сложная или содержит шелл-пайпы, деплой не делает ложных предположений, а выводит рекомендацию добавить `scripts.build`.
