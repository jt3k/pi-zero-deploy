# Proposal

## Why

В текущей версии `pizdeploy` жестко предполагает наличие скрипта сборки `scripts.build` в `package.json` и всегда выполняет `bun run build`. Для простых скриптов или микросервисов (например, простой HTTP-сервер на Node.js или бот из одного файла без отдельного шага сборки) отсутствие `scripts.build` приводит к падению деплоя с ошибкой. При этом ручная настройка сборки бандлером для элементарных проектов избыточна, а передавать `node_modules` на одноплатник неэффективно.

## What Changes

- **Сохранение существующего поведения при наличии `scripts.build`**: если скрипт `build` явно задан в `package.json`, `pizdeploy` выполняет его как обычно (`bun run build`), не меняя логику.
- **Эвристический автобилд при отсутствии `scripts.build`**:
  - Если скрипта `build` нет в `package.json`, система анализирует команду запуска `scripts.start`.
  - Эвристически определяет входной файл приложения (например, `node ./app.js`, `node src/server.js`, `node index.mjs`).
  - Выполняет встроенную оптимизирующую сборку через bun: `bun build '<входной-файл>' --target=node --outfile=./dist/<имя>.mjs --minify`.
  - Адаптирует команду запуска в `ExecStart` systemd-юнита на запуск полученного ESM-бандла: `/usr/bin/node <имя>.mjs`.
- **Понятная диагностика и подсказки**:
  - Если скрипта `build` нет и эвристический парсер не может однозначно распознать входной файл в `scripts.start` (например, нестандартный бинарник или сложная составная команда), деплой завершается с понятной ошибкой и конкретной рекомендацией, как оформить `scripts.start` или добавить `scripts.build`.

### Modified Capabilities
- `deploy-pipeline`: Поддержка фазы автоматической сборки (autobuild) при отсутствии пользовательского `scripts.build` перед формированием дистрибутива `./dist`.
- `user-unit-runtime`: Адаптация команды запуска в `ExecStart` под результат эвристической сборки (`<имя>.mjs`), если выполнялся автобилд.

## Impact

- `src/index.ts`: функция детекции/эвристики входного файла из `scripts.start`, выполнение `bun build` при отсутствии `pkg.scripts.build`, адаптация `ExecStart` для сгенерированного файла.
- `test/deploy.test.ts`: тесты сценариев без `scripts.build` (автобилд в `dist/<имя>.mjs`, запуск через node, сохранение старого поведения при наличии `scripts.build`, диагностика ошибок при нераспознанном `start`).
