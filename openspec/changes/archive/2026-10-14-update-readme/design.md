# Design

## Context

Документация [`README.md`](file:///Users/jt3k/work/pizdeploy/README.md) описывает процесс деплоя, требования и интерфейс CLI утилиты `pizdeploy`. За время реализации изменений (оптимизация времени деплоя, добавление эвристического автобилда, очистка логов, стандартизация подкоманд) в коде изменились параметры выдержки (с 20 с на 5 с), состав вывода `ps` (5 колонок без `Service`), удалена зависимость от `npm` на удалённом хосте и убрана строка «порт не задан» из финального сообщения об успехе. Документация должна быть синхронизирована с фактическим поведением.

## Goals / Non-Goals

**Goals:**
- Привести все примеры команд, ASCII-таблицы и текстовые описания в [`README.md`](file:///Users/jt3k/work/pizdeploy/README.md) в точное соответствие с кодом [`src/index.ts`](file:///Users/jt3k/work/pizdeploy/src/index.ts).
- Описать автоматическую сборку через `bun build` при отсутствии `scripts.build`.
- Устранить устаревшие ссылки на `npm` на целевой машине.

**Non-Goals:**
- Изменение кода утилиты, тестов или спецификаций `openspec/specs/`.
- Добавление колонки `Service` в код `pizdeploy ps` (текущая реализация из 5 колонок соответствует утверждённой спецификации `service-discovery`).

## Decisions

### 1. Таблица `pizdeploy ps`: удаление колонки `Service`
- **Решение**: Привести пример таблицы в README к реальному выводу `console.table(rows)`: колонки `Project`, `Release`, `Status`, `URL`, `PID`. Удалить пояснение про поиск cgroup, так как определение статуса опирается на сокеты `ss -tlpn` и `ActiveState`/`MainPID` юнита.
- **Альтернатива**: Добавить колонку `Service` в код. Отклонено: усложняет скрипт сбора на слабом процессоре Pi Zero без практической пользы (имя сервиса совпадает с именем проекта или выводится статусом).

### 2. Время выдержки в разделе «Верификация и таймаут»
- **Решение**: Указать `5 с` для стабильной выдержки счётчика `NRestarts` (константа `STABLE_HOLD_MS = 5_000`) и интервал опроса `1 с` (`VERIFY_INTERVAL_MS = 1_000`).
- **Альтернатива**: Оставить 20 с. Отклонено: дезинформирует пользователя о реальном времени ожидания деплоя.

### 3. Описание сборки и требований
- **Решение**: В разделе «Требования» указать, что на целевом хосте требуется рантайм `Node.js` (`/usr/bin/node`), а `npm` не требуется. В разделе «Сборка» указать, что при наличии `scripts.build` выполняется он, а при отсутствии — автоматическая сборка входного файла через `bun build --target=node --outfile=./dist/<name>.mjs --minify`.

### 4. Корректировка примера `--dry-run`
- **Решение**: Заменить `npm start` в примере вывода на реальный вид команды запуска: `/usr/bin/node dist/index.js` (или адаптированный путь без `dist/`).

## Risks / Trade-offs

- **[Риск]**: Пользователи могут ожидать колонку `Service` в `ps`, если читали старый README.  
  → **Смягчение**: Имя сервиса детерминированно формируется из имени проекта (`<name>.service`) или задаётся в `pizdeploy.service`, поэтому отдельная колонка в таблице избыточна.
