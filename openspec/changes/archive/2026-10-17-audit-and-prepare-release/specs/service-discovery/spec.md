# Spec Delta

## MODIFIED Requirements

### Requirement: Обнаружение задеплоенных проектов и активных релизов

Система SHALL сканировать удалённую директорию `$HOME/projects/*` в домашнем каталоге подключённого пользователя, определять имя каждого задеплоенного проекта и вычислять его текущий активный релиз на основе таргета симлинка `current`.

#### Scenario: Определение активного релиза

- **WHEN** выполняется инспекция проектов
- **THEN** для каждого каталога в `$HOME/projects/*` определяется имя проекта
- **AND** считывается значение симлинка `current` для получения идентификатора релиза (например, `<name>_<hash>`)
- **AND** если симлинк отсутствует или повреждён, релиз помечается как отсутствующий (`-`)

### Requirement: Сбор активных слушающих процессов и служб systemd

Система SHALL обнаруживать запущенные сервисы двумя способами: (1) через анализ слушающих сокетов `ss -tlpn` со строгим сопоставлением PID с рабочей директорией проектов в домашнем каталоге пользователя; (2) через опрос `systemctl --user` для проектов, у которых не найден слушающий процесс, но существует одноимённый пользовательский юнит. Для процессов под управлением пользовательского менеджера systemd система SHALL брать последнее совпадение имени службы в пути cgroup, а не первое. Второй способ SHALL использоваться как фоллбэк только для проектов, не обнаруженных первым способом.

#### Scenario: Сопоставление запущенного процесса с проектом

- **WHEN** процесс слушает входящие соединения на локальном порту
- **AND** его рабочая директория `/proc/<pid>/cwd` совпадает с каталогом проекта `$HOME/projects/<name>` или является его поддиректорией
- **THEN** статус проекта помечается как `running`
- **AND** фиксируются его сетевой порт, идентификатор процесса PID

#### Scenario: Служба пользовательского менеджера

- **WHEN** процесс принадлежит пользовательскому юниту и его путь cgroup содержит служебный юнит пользователя выше целевого
- **THEN** в качестве имени службы отображается имя самого юнита проекта, а не обёртка пользовательской сессии

#### Scenario: Изоляция проектов с похожими префиксами имён

- **WHEN** в `$HOME/projects` существуют проекты с префиксными именами (например, `app` и `app-worker`)
- **AND** запущен процесс, чей рабочий каталог находится внутри `app-worker`
- **THEN** проект `app` не сопоставляется с этим процессом и не перехватывает его статус

#### Scenario: Проект не запущен

- **WHEN** ни один слушающий процесс не имеет рабочей директории внутри проекта
- **AND** нет активного пользовательского юнита `<name>.service` в systemd
- **THEN** статус проекта помечается как `inactive`
- **AND** порт и PID помечаются как отсутствующие (`-`)

#### Scenario: Бесполтовый сервис обнаружен через systemd

- **WHEN** проект не обнаружен через `ss -tlpn` (не слушает TCP-порт)
- **AND** на хосте существует активный пользовательский юнит `<name>.service` с MainPID > 0
- **THEN** статус проекта помечается как `running`
- **AND** фиксируется PID основного процесса из `MainPID`
- **AND** порт помечается как отсутствующий
