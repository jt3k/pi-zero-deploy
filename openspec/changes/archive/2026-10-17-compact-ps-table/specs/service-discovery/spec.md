# Spec Delta

## MODIFIED Requirements

### Requirement: Форматирование таблицы статусов и кликабельных ссылок

Система SHALL выводить собранную информацию в терминал в виде структурированной таблицы через встроенный API Bun `console.table()` со столбцами `Release`, `Status`, `URL`, `PID`. Таблица SHALL объединять имя проекта и идентификатор релиза в одном столбце `Release` с позиционным выравниванием и позволять различить проект без развёрнутого релиза и проект с развёрнутым, но не запущенным релизом.

#### Scenario: Отображение таблицы статуса

- **WHEN** завершён сбор данных с удалённого сервера
- **THEN** формируется таблица со столбцами `Release`, `Status`, `URL`, `PID`
- **AND** отдельные столбцы `Project` и `Service` отсутствуют
- **AND** для запущенных проектов со слушающим портом формируется ссылка вида `http://<host>:<port>`
- **AND** таблица выводится в консоль стандартным методом `console.table()`

#### Scenario: Компактное форматирование столбца Release с выравниванием

- **WHEN** формируются строки таблицы `Release` для отображения
- **THEN** система вычисляет максимальную длину имени среди всех обнаруженных проектов (`maxProjectLen`)
- **AND** для каждого проекта выводится имя проекта, выровненное пробелами по левому краю до `maxProjectLen`
- **AND** после пробельного разделителя с правого края выводится 5-символьный хеш релиза (например, `kmp     3ea25`, `my-app  00f62`)

#### Scenario: Развёрнутый, но не запущенный проект

- **WHEN** у проекта присутствует активный релиз, но ни один процесс не активен
- **THEN** строка проекта отображается со статусом `inactive` и непустым значением релиза с выровненным хешем
- **AND** отсутствие ссылок и PID не делает строку неотличимой от проекта без релиза

#### Scenario: Проект без активного релиза

- **WHEN** у проекта отсутствует корректный симлинк активного релиза
- **THEN** имя проекта выравнивается по левому краю, а на месте хеша отображается дефис (`-`)
