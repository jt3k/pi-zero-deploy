# Design

## Context

В предыдущей итерации было реализовано форматирование завершённых шагов деплоя с замером времени и зелёной галочкой `✓` в стиле `bun test`. Однако вывод происходит только постфактум: во время исполнения длительных шагов (сборка бандла, загрузка по сети через `scp`, верификация готовности службы) пользователь не видит, какая именно операция сейчас выполняется. Кроме того, код замера времени и логирования размазан по всему конвейеру `handleDeploy`. Требуется декларативная функция выполнения шагов `withStep` с интерактивным спиннером в стиле snake game.

## Goals / Non-Goals

**Goals:**

- Реализовать функцию `withStep<T>(label, action, options?)`, инкапсулирующую запуск действия, замер длительности (`performance.now()`), анимацию ожидания и вывод результата.
- Реализовать компактный односимвольный спиннер анимации в стиле snake game (циклическое движение сегмента змейки по периметру матрицы символа Брайля).
- В интерактивном TTY-терминале отображать спиннер перед названием активного шага, а по завершении шага атомарно перезаписывать строку финальным результатом `✓ <label> [XX.XXms]` (или `✗ <label> [XX.XXms]` при сбое).
- В не-TTY окружении (пайпы, CI, прогон тестов) спиннер полностью отключается, предотвращая вывод управляющих последовательностей ANSI и утечку таймеров `setInterval`.
- Перевести шаги конвейера `handleDeploy` и `runStep` на декларативный вызов `withStep`.

**Non-Goals:**

- Многострочные сложные TUI/интерфейсы на full-screen curses. Спиннер работает исключительно на текущей строке терминала через возврат каретки (`\r\x1b[K`).
- Изменение семантики и кодов возврата CLI.

## Decisions

### 1. Односимвольная анимация Snake Spinner

Для анимации змейки в рамках одного символа используется циклическая последовательность сегментов символов Брайля (8-фазный цикл змейки, ползущей по контуру ячейки):
`['⠋', '⠙', '⠚', '⠒', '⠂', '⠂', '⠒', '⠲', '⠴', '⠤', '⠄', '⠄', '⠤', '⠦', '⠖', '⠒']`
Частота обновления — 80 мс.
Перед шагом в TTY выводится: `${frame} ${label}` (с очисткой строки `\r\x1b[K`).
При завершении интервал очищается (`clearInterval`), и строка перезаписывается: `\r\x1b[K✓ ${label} [${duration}]\n`.

_Альтернативы_: Использовать emoji 🐍 или мультисимвольную змейку. Отклонено: пользователь прямо запросил «из одного символа», а символы Брайля занимают ровно 1 моноширинную колонку и не ломают выравнивание в терминале.

### 2. Декларативная абстракция `withStep`

Сигнатура:

```ts
export async function withStep<T>(
  label: string,
  action: () => Promise<T>,
  options?: {
    isSuccess?: (result: T) => boolean;
  },
): Promise<T>;
```

По умолчанию `isSuccess`:

- если `result` — число (`number`), успехом считается `result === 0`;
- если `result` — объект с полем `exitCode`, успехом считается `result.exitCode === 0`;
- в остальных случаях (включая `void`) успехом считается нормальное завершение без выброса исключения.

Если шаг завершился с ошибкой (ненулевой код или исключение), выводится отметка `✗ <label> [XX.XXms]` (или восстанавливается строка для вывода stderr), и результат возвращается / исключение пробрасывается наружу.

### 3. Автоматическое отключение в не-TTY

Проверка: `process.stdout.isTTY && !process.env.NO_COLOR && !process.env.CI`.
Если условие не выполняется:

- Таймер `setInterval` не запускается.
- Перед запуском шага в консоль ничего не выводится (или вывод только по завершении).
- По завершении выводится стандартный `formatStepSuccess(label, duration)` через `console.log`.

### 4. Неблокирующее асинхронное исполнение удалённых команд (Bun.spawn)

Таймер спиннера (`setInterval` с частотой 80 мс) выполняется в общем потоке Event Loop. Использование синхронных вызовов (`Bun.spawnSync`) приводит к блокировке потока на уровне системного вызова `waitpid`, из-за чего спиннер зависает на первом кадре во время длительных операций (`daemon-reload`, `enable --now ... && restart ...`).

Решение:

- `remoteExec` в `src/ssh.ts` переведён на асинхронный `Bun.spawn` с перехватом `proc.stdout`, `proc.stderr` и ожиданием `proc.exited`.
- Потоки вывода читаются асинхронно через `new Response(proc.stdout).text()`.
- Event Loop остаётся свободным, обеспечивая плавную анимацию змейки на всех этапах деплоя.

## Risks / Trade-offs

- **[Утечка таймеров при исключениях в action]** → Таймер спиннера оборачивается в блок `try ... finally`, гарантируя вызов `clearInterval` в любых непредвиденных ситуациях.
- **[Поломка тестов из-за символов возврата каретки \r]** → В неинтерактивном режиме (включая запуск тестов через `Bun.spawnSync`) `isTTY === false`, поэтому `\r\x1b[K` никогда не попадает в поток тестов.
- **[Зависание анимации из-за блокировки Event Loop]** → Все операции конвейера и запуск подпроцессов (включая SSH) выполняются строго асинхронно, исключая использование `spawnSync` и блокирующих файловых операций.
