# Proposal

## Why

Во время развёртывания и управления службами через `pizdeploy` пользователь длительное время ожидает завершения удалённых операций без промежуточной обратной связи. Наглядный вывод каждого шага в стиле `bun test` с зелёной отметкой `✓`, понятным названием операции и точным временем выполнения в формате `[XX.XXms]` или `[XX.XXs]` делает процесс деплоя прозрачным, информативным и удобным для мониторинга производительности шагов.

## What Changes

- Добавлен вспомогательный модуль форматирования длительности и шагов (`formatDuration`, `formatStepSuccess`), форматирующий время как `[12.34ms]` для интервалов < 1 с и `[1.23s]` для интервалов >= 1 с, с зелёной отметкой `✓` (с поддержкой `NO_COLOR` / TTY).
- Конвейер деплоя (`handleDeploy`) снабжён подробным выводом каждого промежуточного шага: сборка, упаковка, подготовка каталогов, передача архива по scp, проверка/включение linger, распаковка, атомарное переключение current, запись systemd user-юнита, daemon-reload, запуск службы, верификация и ротация версий.
- Команды управления службами (`start`, `stop`, `restart`, `disable`, `remove`) дополнены выводом времени выполнения операции.
- Обновлены тесты конвейера деплоя для проверки вывода шагов в формате `✓ <шаг> [<время>]` и корректного отсутствия финального подтверждения успеха при сбоях.

### Modified Capabilities

- `deploy-pipeline`: добавлены требования к поэтапному логированию шагов конвейера деплоя в стиле `bun test` с символом `✓` и замером времени выполнения.

## Impact

- Затрагиваемые файлы исходного кода: `src/format.ts` (или `src/deploy.ts`), `src/ssh.ts`, `src/service.ts`, `src/index.ts`.
- Затрагиваемые тесты: `test/deploy.test.ts`, `test/cli.test.ts`.
- Внешние зависимости: без добавления сторонних библиотек (используются встроенные возможности Bun / Node.js `performance.now()`).
