# Design

## Context

Мотивация и цели изменений приведены в `proposal.md`.
Ранее в проектах `pi-zero-deploy` использовались громоздкие bash-скрипты или обёртки вокруг `zx`, перегруженные избыточными проверками и сторонними зависимостями. В `pizdeploy` принят курс на максимальную простоту и использование возможностей среды выполнения Bun 1.4 без сторонних библиотек.

## Goals / Non-Goals

**Goals:**
- Полная замена демонстрационного `echo pwd` на конвейер доставки артефактов `dist`.
- Использование нативного Bun Shell `$` и встроенных API (`Bun.CryptoHasher`, `parseArgs` из `util`, `Bun.file`).
- Детерминированное вычисление суффикса релиза: первые 5 символов SHA-256 от `dist.tar.gz`.
- Изолированная доставка в `~/projects/<name>/incoming/<name>_<hash5>` с распаковкой на целевом хосте.
- Атомарное переключение симлинка `current` (`ln -sfn` + `mv -fT`) и перезапуск `systemctl`.
- Автоматическая ротация: сохранение ровно 3 последних релизов в `incoming/`.
- Поддержка флага `--dry-run` с информативным выводом целевого каталога релиза.
- Гарантированная очистка локального `dist.tar.gz` в блоке `finally`.

**Non-Goals:**
- Использование библиотеки `zx` или сторонних NPM-пакетов.
- Поддержка компиляции кода или `bun install` на целевом Raspberry Pi Zero (доставляются исключительно готовые артефакты).
- Интерактивный ввод паролей (строго SSH-ключи, `BatchMode=yes`).

## Decisions

### D1. Отказ от `zx` в пользу встроенных возможностей Bun 1.4
Вместо `zx` используются:
- `import { $ } from "bun"` — встроенный Bun Shell с нативным интерполированием аргументов и методом `.nothrow()`.
- `parseArgs` из `"util"` — стандартный парсер аргументов для флагов `--ssh <host>` и `--dry-run`.
- `new Bun.CryptoHasher("sha256")` — встроенный быстрый криптографический хэшер.
- `Bun.file("package.json").json().catch(() => ({}))` — чтение конфигурации без сторонних парсеров.

### D2. Формирование идентификатора релиза и путей
1. Имя проекта `<name>` извлекается из `package.json` (`pkg.name || "app"`).
2. Хэш архива `hash5` вычисляется как первые 5 символов SHA-256 hex-дайджеста от упакованного `dist.tar.gz`. В режиме `--dry-run` используется фиктивный хэш `mock5` (или хэш существующего архива).
3. Идентификатор релиза: `relId = `${name}_${hash5}``.
4. Пути на Raspberry Pi:
   - `REMOTE_PROJECT_DIR = /home/pi/projects/${name}`
   - `NEW_DIR = ${REMOTE_PROJECT_DIR}/incoming/${relId}`
   - `CURRENT_LINK = ${REMOTE_PROJECT_DIR}/current`

### D3. Конвейер удалённого развёртывания
1. `mkdir -p ${NEW_DIR}` на целевом хосте через `ssh`.
2. Копирование локального `dist.tar.gz` в `${NEW_DIR}/dist.tar.gz` через `scp`.
3. Распаковка и удаление архива на хосте: `cd ${NEW_DIR} && tar -xzf dist.tar.gz && rm dist.tar.gz`.
4. Атомарное переключение симлинка и перезапуск службы:
   `ln -sfn ${NEW_DIR} ${REMOTE_PROJECT_DIR}/current_tmp && mv -fT ${REMOTE_PROJECT_DIR}/current_tmp ${CURRENT_LINK} && sudo systemctl restart ${service}`
   где `${service}` по умолчанию `app.service` (или значение из `pizdeploy.service` в `package.json`).
5. Ротация: удаление старых каталогов в `incoming/` с сохранением 3 последних:
   `cd ${REMOTE_PROJECT_DIR}/incoming && ls -1d * 2>/dev/null | sort | head -n -3 | xargs rm -rf 2>/dev/null || true`.

### D4. Режим `--dry-run`
При передаче флага `--dry-run`:
- Пропускаются локальная сборка `bun run build` и создание архива.
- Пропускаются сетевые вызовы `ssh` и `scp`.
- В консоль выводится желтое информационное сообщение о планируемом развертывании с явным выделением пути `${NEW_DIR}` для удобства копирования.

### D5. Гарантированная локальная очистка
Создание `dist.tar.gz` оборачивается в конструкцию `try / finally`. В секции `finally` локальный файл `dist.tar.gz` удаляется, чтобы не засорять рабочий каталог проекта.

## Risks / Trade-offs

- [Риск: отсутствие `scp` в PATH] → `Bun.which("scp")` проверяется перед передачей файлов; при отсутствии возвращается код 127 с информативным сообщением.
- [Риск: разрыв соединения при передаче большого архива] → использование флагов таймаута `ConnectTimeout=3` и строгий контроль кодов возврата команд.
- [Риск: имя каталога релиза уже существует в incoming] → детерминированный хэш от неизмененного архива гарантирует совпадение путей; `tar -xzf` перезаписывает файлы в целевой папке.
