# Proposal

## Why

Сейчас в `pizdeploy` таблица `pizdeploy ps` отображает все обнаруженные проекты в `/home/pi/projects/*`, а для управления запущенными сервисами доступны только команды `stop` и `disable`. Если пользователь хочет перезапустить сервис, запустить его вручную без повторного деплоя, посмотреть его логи, либо убрать ненужный или заброшенный сервис из вывода таблицы `ps` (отключив службу, удалив unit-файл и сняв активный симлинк `current`), инструментов для этого в CLI нет.

Введение стандартного набора команд жизненного цикла сервиса (`start`, `restart`, `status`, `logs`, `remove`/`rm`), соответствующих общепринятым стандартам systemd/docker/pm2, предоставит пользователю полный и предсказуемый контроль над задеплоенными сервисами прямо из локального терминала или из директории проекта.

## What Changes

1. **Команды управления состоянием сервиса**:
   - `start [name]`: запуск службы (`systemctl --user start <service>`).
   - `restart [name]`: перезапуск службы (`systemctl --user restart <service>`).
   - `status [name]`: просмотр подробного статуса systemd (`systemctl --user status <service>`).
   - `logs [name] [--tail N] [-f]`: просмотр журнала службы через `journalctl --user -u <service>`.

2. **Команда удаления сервиса (`remove` / `rm`)**:
   - `remove [name]` (алиас `rm [name]`): деактивация и снятие проекта с учёта в `ps`:
     - Останавливает службу (`systemctl --user stop <service>`).
     - Отключает автозапуск (`systemctl --user disable <service>`).
     - Удаляет unit-файл из `~/.config/systemd/user/<service>.service` и выполняет `systemctl --user daemon-reload`.
     - Удаляет симлинк `current` в `/home/pi/projects/<name>/current` (чтобы проект перестал отображаться как развернутый и ушёл из таблицы `ps` либо помечался полностью снятым, согласно правилам обнаружения).
     - **Важно**: каталог проекта `/home/pi/projects/<name>` и история релизов в `releases/` сохраняются на диске малинки (пользователь может удалить их вручную при необходимости).

3. **Скрытие неактивных/неразвернутых каталогов в `pizdeploy ps`**:
   - В таблице `ps` отображаются только проекты, имеющие активный симлинк `current` или работающий процесс/службу. Каталоги без `current` (например, после `remove` или пустые) исключаются из таблицы либо явно фильтруются.

4. **Обновление CLI-парсера и Usage**:
   - Расширение списка разрешённых команд: `ps`, `stop`, `disable`, `start`, `restart`, `status`, `logs`, `remove`, `rm`.
   - Обновление сообщения `usage` при ошибках валидации аргументов (код выхода 2).

## Capabilities

### Modified Capabilities

- `cli-command`: расширение CLI новыми подкомандами (`start`, `restart`, `status`, `logs`, `remove`/`rm`), обновление `usage` и кодов возврата.
- `service-lifecycle`: добавление операций запуска (`start`), перезапуска (`restart`), просмотра статуса (`status`), логов (`logs`) и полного снятия службы (`remove`/`rm` с очисткой unit-файла).
- `service-discovery`: обновление логики обнаружения проектов в `pizdeploy ps` (исключение проектов без `current` и без активных процессов).

## Impact

- `src/index.ts`: расширение парсера аргументов, добавление обработчиков команд жизненного цикла и логики `remove`, обновление `buildPsScript` при необходимости.
- `test/cli.test.ts` & `test/deploy.test.ts`: тесты на новые команды, флаги и вывод `ps`.
- `README.md`: документация по всем доступным сервисным командам (`start`, `restart`, `status`, `logs`, `remove`).
