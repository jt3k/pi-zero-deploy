# deploy-pipeline Specification

## Purpose

Определяет конвейер безопасного развёртывания релизов через буферную директорию staging (incoming), распаковку в постоянное хранилище релизов (releases), атомарное переключение активной версии (current) и ротацию версий.

## Requirements

### Requirement: Доставка архива через временный буфер incoming

Система SHALL подготавливать артефакт в каталоге `./dist` и загружать собранный архив `dist.tar.gz` во временную буферную директорию `~/projects/<name>/incoming/`, изолируя процесс передачи от каталога релизов. Если в `package.json` задан скрипт `scripts.build`, система SHALL выполнять его (`bun run build`). Если скрипт `scripts.build` отсутствует, система SHALL эвристически определять входной файл из `scripts.start` и автоматически выполнять сборку бандла в `./dist/<имя>.mjs` с помощью `bun build`. Если скрипт `build` отсутствует и входной файл не удалось определить, деплой SHALL прерываться с информативным сообщением об ошибке и рекомендацией. Служебные файлы (unit-файлы) через этот буфер не передаются. Подготовка каталогов `incoming` и `releases` может совмещаться с инициализацией удалённого окружения для сокращения сетевых задержек.

#### Scenario: Сборка при наличии скрипта build
- **WHEN** в `package.json` присутствует поле `scripts.build`
- **THEN** система выполняет пользовательский скрипт `bun run build`
- **AND** упаковывает полученный каталог `./dist`

#### Scenario: Автоматическая эвристическая сборка при отсутствии скрипта build
- **WHEN** в `package.json` отсутствует поле `scripts.build`
- **AND** в `scripts.start` указан запускаемый файл (например, `node ./app.js` или `node src/server.js`)
- **THEN** система компилирует входной файл в `./dist/<имя>.mjs` с помощью `bun build` с флагами `--target=node` и `--minify`
- **AND** упаковывает каталог `./dist` для доставки на хост

#### Scenario: Нераспознанный скрипт start при отсутствии build
- **WHEN** в `package.json` отсутствует `scripts.build`
- **AND** поле `scripts.start` содержит нераспознанную команду без явного файла точки входа
- **THEN** деплой прерывается до выполнения сетевых команд
- **AND** в stderr выводится подсказка с рекомендацией, как оформить `scripts.start` или добавить `scripts.build`

#### Scenario: Успешная загрузка архива
- **WHEN** выполняется передача файлов релиза на удалённый хост
- **THEN** архив копируется по пути `~/projects/<name>/incoming/dist.tar.gz`
- **AND** в каталоге `releases` не создаётся незавершённых или повреждённых директорий

#### Scenario: Юнит не передаётся как файл проекта
- **WHEN** в деплоящем проекте присутствует каталог `systemd/`
- **THEN** его содержимое не копируется в `incoming/` и не участвует в конвейере доставки

### Requirement: Распаковка в постоянный каталог releases

Система SHALL распаковывать полученный архив из `incoming/` в постоянную директорию релиза `~/projects/<name>/releases/<name>_<hash5>` и удалять временный архив из `incoming/`.

#### Scenario: Распаковка релиза
- **WHEN** архив полностью доставлен на хост
- **THEN** создается директория `~/projects/<name>/releases/<name>_<hash5>`
- **AND** архив распаковывается внутрь этой директории
- **AND** временный файл `dist.tar.gz` в `incoming/` удаляется

### Requirement: Атомарное переключение симлинка current

Система SHALL атомарно переключать симлинк `current` на директорию нового релиза в `releases/<name>_<hash5>`.

#### Scenario: Переключение симлинка
- **WHEN** файлы релиза распакованы в `releases/<name>_<hash5>`
- **THEN** создается временный симлинк `current_tmp` с таргетом `releases/<name>_<hash5>`
- **AND** выполняется атомарная замена `current` через `mv -fT`

### Requirement: Ротация релизов в директории releases

Система SHALL выполнять ротацию старых версий в директории `releases/`, сохраняя последние 3 релиза и удаляя более старые. Сбой ротации не должен влиять на код возврата уже успешно выполненных шагов конвейера.

#### Scenario: Очистка старых версий
- **WHEN** новый релиз успешно активирован
- **THEN** список директорий в `releases/` сортируется по имени
- **AND** удаляются все версии, кроме 3 самых последних

#### Scenario: Ротация не скрывает чужих ошибок
- **WHEN** любой из предшествующих шагов конвейера завершился с ненулевым кодом возврата
- **THEN** итоговый код возврата конвейера ненулевой
- **AND** сообщение об успешном развёртывании не выводится

### Requirement: Каждый шаг конвейера проверяется по коду возврата

Система SHALL выполнять шаги удалённого конвейера так, чтобы ненулевой код возврата любого значимого шага приводил к ненулевому итоговому коду возврата и к отсутствию сообщений об успехе. Шаги могут пакетироваться в согласованные составные команды для сокращения RTT, при этом сбой любой подкоманды в пакете обязан немедленно прерывать выполнение с ненулевым кодом.

#### Scenario: Отказ шага установки службы
- **WHEN** шаг записи или включения user-юнита завершается с ошибкой
- **THEN** утилита завершается с ненулевым кодом возврата
- **AND** в stderr выводится причина отказа
- **AND** stdout не содержит подтверждения успеха

#### Scenario: Отказ шага доставки
- **WHEN** передача архива или его распаковка завершаются ошибкой
- **THEN** утилита завершается с ненулевым кодом возврата
- **AND** симлинк `current` остаётся на предыдущем релизе

### Requirement: Полузавершённое состояние не выдаётся за успех

Система SHALL не переключать симлинк `current` до тех пор, пока целевой релиз не распакован полностью, и SHALL возвращать `current` на предыдущий релиз только при условии, что предыдущий релиз реально существовал на удалённом хосте. Если предыдущего релиза не существовало (первый деплой), симлинк `current` SHALL удаляться при сбое верификации во избежание создания циклического симлинка.

#### Scenario: Отказ после распаковки
- **WHEN** архив распакован, но активация службы не подтверждена
- **THEN** симлинк `current` указывает на предыдущий релиз (если он существовал)
- **AND** новый каталог релиза остаётся на диске

#### Scenario: Отказ после распаковки при наличии предыдущего релиза
- **WHEN** архив распакован, но активация службы не подтверждена
- **AND** до начала деплоя существовал валидный предыдущий релиз
- **THEN** симлинк `current` указывает на предыдущий релиз
- **AND** новый каталог релиза остаётся на диске

#### Scenario: Отказ при первом деплое проекта
- **WHEN** происходит первый деплой проекта (предыдущего релиза не было)
- **AND** активация службы не подтверждена
- **THEN** временный или некорректный симлинк `current` удаляется
- **AND** не создаётся симлинк, указывающий сам на себя
- **AND** утилита завершается с ненулевым кодом ошибки
