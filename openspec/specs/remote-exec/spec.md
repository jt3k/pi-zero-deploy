# remote-exec Specification

## Purpose

Определяет, как pizdeploy выбирает целевой хост, формирует и выполняет удалённую команду по SSH, а также как транслирует вывод и коды возврата обратно в терминал пользователя.

## Requirements

### Requirement: Адрес подключения разрешается с фиксированным приоритетом

Система SHALL определять адрес подключения как первое непустое значение из: флаг `--ssh`, поле `pizdeploy.ssh` в файле `package.json` текущего рабочего каталога вызова, значение по умолчанию `pi@zero.local`.

#### Scenario: Флаг перебивает конфигурацию

- **WHEN** в package.json текущего каталога задано `pizdeploy.ssh = "pi@from-config.local"`, а пользователь выполняет `pizdeploy --ssh pi@from-flag.local`
- **THEN** подключение выполняется к `pi@from-flag.local`

#### Scenario: Конфигурация без флага

- **WHEN** в package.json текущего каталога задано `pizdeploy.ssh = "pi@from-config.local"` и пользователь выполняет `pizdeploy` без флага
- **THEN** подключение выполняется к `pi@from-config.local`

#### Scenario: Значение по умолчанию

- **WHEN** ни флаг, ни package.json текущего каталога не задают адрес
- **THEN** подключение выполняется к `pi@zero.local`

#### Scenario: Родительский package.json не используется

- **WHEN** пользователь выполняет `pizdeploy` из каталога без package.json, а в родительском каталоге задан package.json с `pizdeploy.ssh`
- **THEN** подключение выполняется к значению по умолчанию `pi@zero.local`

### Requirement: Удалённая команда получает текущий рабочий каталог

Система SHALL сформировать удалённую команду `echo 'pwd: <рабочий каталог>'`, где `<рабочий каталог>` — абсолютный путь каталога, из которого запущен `pizdeploy`, и передать его безопасно, без риска выполнения произвольного кода из имени каталога.

#### Scenario: Каталог без специальных символов

- **WHEN** пользователь выполняет `pizdeploy` из каталога `/tmp/lololo`
- **THEN** stdout содержит ровно `pwd: /tmp/lololo\n`

#### Scenario: Каталог с пробелом в имени

- **WHEN** пользователь выполняет `pizdeploy` из каталога `/tmp/my dir`
- **THEN** stdout содержит ровно `pwd: /tmp/my dir\n`
- **AND** удалённая команда выполняется успешно (код возврата 0)

#### Scenario: Каталог с одинарной кавычкой в имени

- **WHEN** пользователь выполняет `pizdeploy` из каталога, имя которого содержит одинарную кавычку
- **THEN** stdout содержит `pwd: <полный путь с кавычкой>`
- **AND** на сервере не выполняется никаких команд помимо сформированной

### Requirement: Подключение выполняется через системный клиент OpenSSH

Система SHALL выполнять подключение через исполняемый файл `ssh`, найденный в `PATH`, без собственных реализаций SSH-протокола и без явного отключения пользовательских настроек (`~/.ssh/config`, `ProxyJump`, ssh-агент продолжают действовать).

#### Scenario: Хост описан в ~/.ssh/config

- **WHEN** адрес подключения — это имя хоста из `~/.ssh/config`, а не `user@host`
- **THEN** подключение выполняется с параметрами из этого конфига и завершается успешно

#### Scenario: Требуется интерактивный ввод пароля

- **WHEN** доступ по ключу не настроен и `ssh` запрашивает пароль
- **THEN** утилита не зависает в ожидании ввода, а завершается с ненулевым кодом возврата и сообщением об ошибке в stderr

### Requirement: Отсутствие ssh в PATH сообщается явно

Система SHALL при недоступном в `PATH` исполняемом файле `ssh` завершиться с кодом возврата 127 и сообщением в stderr, указывающим на отсутствие `ssh`.

#### Scenario: ssh не установлен

- **WHEN** пользователь выполняет `pizdeploy`, а `ssh` недоступен в `PATH`
- **THEN** в stderr появляется сообщение, содержащее `ssh`
- **AND** код возврата равен 127
- **AND** stdout пуст

### Requirement: Сетевые ошибки не маскируются

Система SHALL при недоступности хоста или отказе подключения вывести сообщение `ssh` в stderr, не добавлять сообщений в stdout и завершиться с ненулевым кодом возврата.

#### Scenario: Хост не отвечает

- **WHEN** целевой хост недоступен по сети
- **THEN** stdout пуст
- **AND** в stderr присутствует сообщение об ошибке подключения
- **AND** код возврата ненулевой

### Requirement: Защита от аргументных инъекций OpenSSH

Система SHALL валидировать адрес целевого хоста перед передачей клиентам OpenSSH (`ssh`, `scp`) и использовать безопасное разделение аргументов, предотвращая внедрение флагов вроде `-oProxyCommand`.

#### Scenario: Хост с дефисом в начале имени отклоняется

- **WHEN** целевой адрес хоста начинается с дефиса (`-`)
- **THEN** утилита отклоняет адрес с сообщением о нарушении безопасности
- **AND** сетевые клиенты `ssh` и `scp` не вызываются
- **AND** код возврата ненулевой
