# service-lifecycle Specification

## Purpose

Обеспечивает удалённое управление жизненным циклом служб systemd на хосте: остановку запущенного процесса службы и отключение её автоматического запуска при старте системы.

## Requirements

### Requirement: Остановка процесса службы на удалённом хосте

Система SHALL останавливать процесс целевой службы на удалённом хосте командой `systemctl --user stop <service>` от имени подключаемого пользователя, без привилегий суперпользователя, с разрешением имени службы из аргументов командной строки или локального `package.json`.

#### Scenario: Остановка службы по явно переданному имени

- **WHEN** пользователь выполняет `pizdeploy stop my-app`
- **THEN** имя службы нормализуется до `my-app.service`
- **AND** на удалённом хосте выполняется `systemctl --user stop my-app.service`
- **AND** в консоль выводится подтверждение остановки службы

#### Scenario: Остановка службы по умолчанию из проекта

- **WHEN** пользователь выполняет `pizdeploy stop` без указания имени
- **THEN** имя службы извлекается из `package.json` (`pizdeploy.service` или `name.service`, по умолчанию `app.service`)
- **AND** на удалённом хосте выполняется `systemctl --user stop <service>`

#### Scenario: Целевая служба не найдена

- **WHEN** на удалённом хосте указанная служба отсутствует в пользовательском менеджере
- **THEN** утилита сообщает в терминале, что служба не найдена, и завершается с ненулевым кодом ошибки

#### Scenario: Остановка не требует пароля

- **WHEN** на хосте `sudo` недоступен без пароля
- **THEN** остановка службы завершается успешно

### Requirement: Отключение автозапуска службы на удалённом хосте

#### Scenario: Отключение автозапуска службы по умолчанию из проекта

### Requirement: Запуск процесса службы на удалённом хосте

Система SHALL запускать процесс целевой службы командой `systemctl --user start <service>` от имени подключаемого пользователя без привилегий суперпользователя.

#### Scenario: Запуск службы по явно переданному имени

- **WHEN** пользователь выполняет `pizdeploy start my-app`
- **THEN** имя службы нормализуется до `my-app.service`
- **AND** на удалённом хосте выполняется `systemctl --user start my-app.service`
- **AND** в консоль выводится подтверждение запуска службы

#### Scenario: Запуск службы по умолчанию из проекта

- **WHEN** пользователь выполняет `pizdeploy start` без указания имени

- **AND** на удалённом хосте выполняется `systemctl --user start <service>`

### Requirement: Перезапуск процесса службы на удалённом хосте

Система SHALL перезапускать процесс целевой службы командой `systemctl --user restart <service>` от имени подключаемого пользователя без привилегий суперпользователя.

#### Scenario: Перезапуск службы по явно переданному имени

- **AND** в консоль выводится подтверждение перезапуска службы

#### Scenario: Перезапуск службы по умолчанию из проекта

- **WHEN** пользователь выполняет `pizdeploy restart` без указания имени
- **THEN** имя службы извлекается из `package.json` (`pizdeploy.service` или `name.service`, по умолчанию `app.service`)
- **AND** на удалённом хосте выполняется `systemctl --user restart <service>`

### Requirement: Просмотр статуса службы на удалённом хосте

Система SHALL запрашивать и выводить в stdout статус целевой службы командой `systemctl --user status <service>` от имени подключаемого пользователя без привилегий суперпользователя.

#### Scenario: Просмотр статуса службы

- **WHEN** пользователь выполняет `pizdeploy status my-app`
- **THEN** на удалённом хосте выполняется `systemctl --user status my-app.service`
- **AND** результат выводится пользователю без изменений

### Requirement: Просмотр логов службы на удалённом хосте

Система SHALL запрашивать и выводить в stdout журнал службы командой `journalctl --user -u <service> -n 50 --no-pager` от имени подключаемого пользователя без привилегий суперпользователя.

#### Scenario: Просмотр последних записей журнала

- **WHEN** пользователь выполняет `pizdeploy logs my-app`
- **THEN** на удалённом хосте запрашиваются последние записи журнала службы через `journalctl --user -u my-app.service -n 50 --no-pager`
- **AND** журнал отображается в stdout

### Requirement: Удаление и снятие службы с учёта

Система SHALL останавливать службу, отключать её автозапуск, удалять её файл unit из `~/.config/systemd/user/<service>`, выполнять перезагрузку демона пользовательского systemd и удалять симлинк `current` каталога проекта в домашней директории подключенного пользователя, сохраняя при этом директорию проекта и историю версий в `releases/`.

#### Scenario: Успешное удаление службы

- **WHEN** пользователь выполняет `pizdeploy remove my-app` или `pizdeploy rm my-app`
- **THEN** служба останавливается (`systemctl --user stop my-app.service`)
- **AND** служба отключается (`systemctl --user disable my-app.service`)
- **AND** файл `~/.config/systemd/user/my-app.service` удаляется
- **AND** выполняется `systemctl --user daemon-reload`
- **AND** симлинк `$HOME/projects/my-app/current` удаляется
- **AND** каталог `$HOME/projects/my-app/releases` сохраняется на диске
- **AND** выводится сообщение об успешном удалении службы

### Requirement: Строгая валидация имени службы и проекта

Система SHALL проверять имя службы и проекта на соответствие безопасному шаблону идентификаторов (разрешены буквы, цифры, дефис, точка и подчеркивание) до подстановки в удалённые команды управления службами, отклоняя любые спецсимволы shell.

#### Scenario: Попытка инъекции в имени службы

- **WHEN** в команду управления службой (`start`, `stop`, `restart`, `status`, `logs`, `disable`, `remove`) передано имя со спецсимволами shell
- **THEN** операция отклоняется с сообщением об ошибке валидации
- **AND** удалённые команды на хосте не выполняются
- **AND** код возврата ненулевой

### Requirement: Подтверждение команд управления службой с замером времени

Система SHALL сопровождать успешное выполнение команд управления жизненным циклом службы (`start`, `stop`, `restart`, `disable`, `remove`) отметкой `✓` и указанием затраченного времени в формате `[XX.XXms]` или `[XX.XXs]`.

#### Scenario: Остановка службы с замером времени

- **WHEN** пользователь выполняет команду `pizdeploy stop <service>`
- **THEN** после успешной остановки процесса службы выводится строка подтверждения с отметкой `✓` и временем выполнения `[XX.XXms]` или `[XX.XXs]`

#### Scenario: Запуск или перезапуск службы с замером времени

- **WHEN** пользователь выполняет `pizdeploy start <service>` или `pizdeploy restart <service>`
- **THEN** после успешного выполнения операции выводится строка подтверждения с отметкой `✓` и временем выполнения `[XX.XXms]` или `[XX.XXs]`
